# Final report: October 2026 consolidation

**Date:** 2026-10-12. **Repository:** `github.com/Alashabeeb/ChatBot`, branch `main`.
**Production:** still `c0e2010` until `main` is deployed.

Tests use stubs, local stand-in servers and captured fixtures only. The live model, OpenSearch and
Wazuh were never called, and nothing was pushed except where you asked. The detail behind every line
is in `docs/MERGE_DECISIONS.md` (decisions per phase) and `docs/FINDINGS.md` (findings F-00 to F-66).

**Checker score.** Until the Windows capture exists, "checker score" means the pipeline evaluation:
four invented scenarios (five from Phase 5) run through the real pipeline with a faithful and an
adversarial stub model, scored by `evals/check.py`. "Legacy" is the same adversarial output shown
verbatim, as the code before Phase 4 would have shown it.

## Phase 0: Hotfix

**Changed:**
- The tools that fabricated results were unregistered: mock threat intel, the fake IP block, the fake process list.
- Added a read-only audit of saved messages and memories.

**Tests:** 6.

**Unsure about:** nothing outstanding.

## Phase 1: Merge

**Changed:**
- The `ChatBot-main` hardening work was merged into `main`: run records, fixture capture and replay, no JWT fallback secret, history sanitising, and honest fallbacks.
- At your request, a ChatGPT-style chat with streaming was added alongside Search Wazuh.

**Tests:** 48 at the merge, 62 backend and 5 frontend after the chat work.

**Unsure about:** nothing outstanding.

## Phase 2: Close every known defect

**Changed:**
- **Action tools:** they say plainly what they can't do, and blocking an IP requires a human approval for those exact parameters.
- **Model calls:** every call has a time limit, and a hang falls back cleanly.
- **Planner input:** memories reach the planner as data, never with system authority.
- **Auth:** checks the database on every request; the default admin must change its password; a weak `JWT_SECRET` stops the backend starting.
- **Fixes:** evidence is kept per tool call; the purge dry run is read-only; the OpenSearch URL is no longer logged.
- **UI:** every record in View Full Details is labelled by source, and every status claim nothing backed was removed.
- **Security updates:** `npm audit fix` applied to the backend.

**Tests:** 93 backend, 10 frontend.

**Unsure about:**
- P4: the time limits.
- P9: the password policy.
- P10: a weak secret now blocks startup.
- P14: the audit fix also updated `axios` and `proxy-addr`.

## Phase 3: Measurement harness

**Changed:**
- `evals/STANDARD.md` defines a good answer: 10 hard checks and a 0–100 score.
- `evals/check.py` implements it.
- 29 SYNTHETIC validation cases, generated by the real capture code.
- Replay writes baseline records.
- Capture bundle rebuilt from `b346a38`.

**Found and fixed:**
- Replay would have called the live model on the Windows host.
- Replay wrongly reported a divergence when a search had failed during capture.

**Tests:** 99 backend. Every hard check was mutation-checked.

**Checker score:** the self-test validates the checker itself. The baseline is waiting on your capture.

**Unsure about:**
- M9: the score weights.
- The checker only flags what it can identify unambiguously.

## Phase 4: Grounded answers

**Changed:**
- **Cited statements:** the report model returns statements with citations, and code checks each one against the evidence.
- **Unsupported text removed:** invented IPs, rules, techniques not in `rule.mitre.id`, hosts, uncited numbers, scores and claimed actions are dropped and logged, never shown.
- **Code-written opening:** every answer opens with the sources and time window searched.
- **Honest answers** for no data, failed searches, insufficient evidence and output that can't be verified.

**Tests:** 112 backend, with 22 safeguard mutants killed.

**Checker score:**

| | Score | Fabrications reaching the analyst |
|---|---|---|
| Faithful | 100 | 0 |
| Adversarial | 100 | 0 |
| Legacy | 76.6 | 17 |

**Unsure about:**
- G11: the production model has never been asked for the cited-statement format. If it can't follow it, answers become the code-written summary.
- G10 / F-63: sampled counts (fixed in Phase 5).

## Phase 5: Better evidence, faster

**Changed:**
- **Exact counts:** one aggregation request per search counts by rule, agent, source IP, level and technique over every match.
- **Comparison:** each answer compares with the same window a week earlier.
- **Severity floor:** "right now" questions search level 7 and above.
- **Timings:** every run record has per-stage timings.

**Tests:** 123 backend, with 12 mutants killed.

**Checker score and speed:**

| | Before (Phase 4) | After (Phase 5) |
|---|---|---|
| Score, faithful / adversarial | 100 / 100 | 100 / 100 |
| Inflated count shown on sampled evidence | yes | no (F-63 fixed) |
| Report prompt, realistic 200-record search | 15,150 chars | 8,877 chars (−41%) |
| OpenSearch requests per planned search | 2 | 4 |

**Unsure about:**
- A6: the floor level and its trigger phrases.
- F-64: aggregations assume the standard Wazuh field mapping.

## Phase 6: Model flexibility

**Changed:**
- **Separate models:** the planner and report models are configurable separately. Nothing changes by default, and a key only goes to its own endpoint.
- **`evals/compare_models.py`:** compares models side by side on the captured fixtures: score, fabrications shown, statements dropped, format failures, model time, prompt size.
- **Guards:** the comparison refuses any model without a named approval and refuses keys written into its config.

**Tests:** 136 backend, with 11 mutants killed.

**Checker score:** unchanged.

**Unsure about:**
- F-65: only OpenAI-compatible endpoints work.
- No real model has been compared yet.

## Phase 7: Professional conversation

**Changed:**
- **Streaming:** search answers stream only true or verified text: real stages, then the header, then each statement once verified.
- **Follow-ups** reuse the previous search's evidence, with a Search again button.
- **Clarifications:** one short question when a request can't be answered without guessing, never asked twice.

**Tests:** 161 backend, 17 frontend, with 14 mutants killed. Checked in the browser.

**Checker score:** no regression (100 / 100, legacy 76.3 with 23 fabrications).

**Unsure about:**
- C4: when to reuse evidence rather than search again.
- C6: the clarification triggers.
- F-66: follow-up evidence is lost on a restart.

## Phase 8: Keep it good

**Changed:**
- **Release gate** (`evals/gate.py`, run by CI on every push and pull request to `main`, and by `npm run release`). It fails if:
  - any fabrication or hard-check failure reaches an answer;
  - any score drops below `evals/gate_baseline.json`;
  - the checker's self-test breaks;
  - the evaluation stops seeing fabrications.
- **`findRun.js`** finds a run and shows exactly what verification removed.
- **New docs:** `ADDING_TEST_CASES.md`, `WORKING_TOGETHER.md` and `STATUS.md`.

**Tests:** 171 backend, 17 frontend, with 8 gate mutants killed.

**Checker score:** gate baseline 100 / 100 on 10 cases.

**Unsure about:**
- E1: the gate isn't in `npm run build`, because the production host may lack Python.
- E2: CI runs Node 22, and has not run yet.
